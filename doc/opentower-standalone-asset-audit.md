# OpenTower standalone asset audit

This document tracks whether OpenSkyscraper can ship and run without assets
from `SIMTOWER.EXE` / `SIMTOWER.EX_` and without YootTower `.t2p` plugins.
SimTower and YootTower remain supported as optional user-supplied editions and
bonus-plugin sources; they must not be the only source of required base-game
assets.

Audit baseline: 2026-07-09.

## Executive status

- SimTower exposes **75 named bitmap sheets** used or prepared by
  `SimTowerLoader`.
- **26 sheets have integrated first-party OpenTower replacements**.
- The remaining **49 named bitmap sheets do not yet have integrated
  first-party replacements**. Some have loose first-party source art, but a
  loose file is not counted as complete until a plugin/sheet is built and the
  runtime uses it.
- SimTower exposes **48 named sounds**. All 48 files currently under
  `data/sounds` are byte-identical to a fresh SimTower extraction. Therefore
  **0 of 48 are verified first-party replacements**.
- `data/bitmaps.hidden` is extraction/reference material. It is not a
  standalone asset source and must not be counted as coverage.
- Startup no longer requires a SimTower executable or a quota of YootTower
  plugins. All discovered plugins are optional and missing assets use safe
  fallbacks while first-party coverage is completed.

## Collision and edition model

Plugin filenames are not sufficient collision identifiers: `Condo.t2p` and
`OpenTower/Condo` have different catalog names but provide the same logical
facility. Collisions should be detected by a stable logical capability key,
not by path. Suggested keys include:

- `tenant.condo`
- `tenant.office`
- `tenant.hotel.single`
- `transport.stairs`
- `transport.elevator.standard`
- `ui.toolbox`

Each provider should declare its logical key, edition (`opentower`,
`simtower`, `yoottower`, or third-party), compatible sprite layout, and
whether its frames are complete or additive. Resolution should support:

1. **Prefer A**: one provider supplies the logical item and all its art.
2. **Prefer B**: the alternate provider supplies it.
3. **Combine variants**: only when providers declare compatible cell sizes,
   state semantics, anchors, masks, and animation timing. The resolver builds
   a combined variant table rather than concatenating pixels blindly.

The choice should be stored per logical capability, with a global default.
SimTower should appear as an optional theme provider only when the user selects
a legal executable. YootTower and third-party plugins should be discovered
dynamically and remain optional bonus providers.

## Prioritized assets still needed

### Priority 0: required for a recognizable standalone base game

- Core UI: toolbox items/tools/speed, time display/rating, menu background,
  map background/buttons/overlays.
- Shared people sheet and the construction worker/grid/solid sheets.
- Spiral-stair animation strips plus elevator digits and elevator people.
- Lobby entrance overlays (the three lobby background providers are complete).
- Environment: sky, clouds, and skyline.
- First-party replacements or intentional silent substitutes for the common
  construction, cash, elevator, time-of-day, and weather sounds.

### Priority 1: base gameplay facilities

- Cinema and metro.
- Facility-specific people/animation sheets for Condo, Office, Hotel,
  restaurant, housekeeping, and events.
- Facility audio for office, restaurant, fast food, party hall, cinema, and
  metro.

### Priority 2: events, polish, and optional theme parity

- Fire states, emergency helicopter, alert icons, Santa, entrances,
  fire ladders, housekeeping, and generic shops.
- Remaining ambience, rating, car, cinema movie, and novelty sound cues.
- Exact SimTower-layout compatibility assets needed only when offering the
  original theme.

## Work required for a dependency-free release

1. Finish runtime wiring for the generated parking-ramp, shops, and
   housekeeping providers, and build semantically ordered toolbox icons.
2. Create first-party art for gaps with no identified replacement: people and
   animations, metro, cinema, construction, environment, fires/alerts, and any
   elevator/UI components not covered by loose art.
3. Build the first-party UI sheets from `originals/UI` and fill remaining UI
   gaps.
4. Replace or silence all 48 extracted sound cues.
5. Add capability manifests and the per-capability collision resolver described
   above.
6. Keep SimTower selection as an optional theme override and YootTower `.t2p`
   discovery as optional bonus content, never as startup requirements.
7. Add a clean-room CI test that launches with neither a SimTower executable
   nor YootTower `.t2p` files available and asserts that no synthetic fallback
   was used for required resources.
